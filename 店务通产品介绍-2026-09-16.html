店务通 · 银行内部户资金归集与分账 SaaS

针对行业商户（店）的财务需求（务），依托银行内部账户（记账簿专用账户）设计的多收单通道资金归集及清分（通）的行业产品，为连锁品牌、电商平台商户、供应链核心企业提供合规、高效的资金管理方案。

版本：V2026.09 ｜ 资料性质：内部业务介绍材料（含敏感定价口径，对外请以定价表为准）

一、产品定位与业务链路

1.1 一句话定位

店务通是基于银行内部户账户体系，为连锁商户提供多平台收单资金归集、统一对账、灵活分账与合规付款的企业资金分账产品（SaaS + API）。

1.2 底层业务链路（四步闭环）

1

开户

商户及其业务关联方按银行要求在线完成银行内部户（电子记账簿）开户。

2

入金

商户将各收单机构 / 公域平台的结算账号变更为银行内部户，每日接收结算资金入金。

3

分账

商户按实际业务将入金资金分账给供应商、渠道、门店等利益相关方。

4

提现

各方将内部户名下资金提现至开户时绑定的同名银行账户。

1.3 解决的核心痛点

  • 二清合规风险：平台/管理方统一收款后再分发，依托持牌资质与银行内部户体系合规解决；
  • 公转私受限：资金到对公户后再转个人受限，个人卡频繁转账有冻卡风险；
  • 资金分散难管：美团/饿了么/抖音/淘宝/拼多多多平台、多收单机构资金统一归集、统一对账；
  • 分账效率低：账期分佣、上下游结算由人工转账转为系统自动化分账；
  • 财务凭证不合规：提供银行性质账户流水凭证（入金/分账/提现三类电子回单）。

二、主要功能

账户管理

多银行内部户开通与管理（苏商/中信/光大/江西等）；平台、管理方、商户、供应商、渠道等角色灵活定义；支持个人/个体户/企业开户；实名认证、绑卡管理、电子协议、限额与提现周期管理。

资金归集

支持美团、饿了么、京东、淘宝、拼多多、抖音等主流公域平台，以及线下多收单机构结算入金；公域/私域资金区分管理；银行入金白名单机制。

清分付款（分账）

余额分账、固定比例分账、固定金额分账、组合分账；单笔/批量分账；自动结算（D1）/手动结算（D1）；平台分账模式、商户分账模式；支持分账审核流。

综合对账

入金对账、出金对账、多平台对账；自动/手动对账任务；差异重对、手动调整、补录；对平数据一键完成分账。

电子回单

入金回单（收单机构→商户）、分账回单（商户→分账方）、提现回单（提现人→本人）三单体系，满足财务合规要求。

增值服务与输出

餐饮供应链 SaaS、上下游采购（付费开通）；SaaS 管理后台 + 小程序一站式操作；API 接口对接（需单独申请）；角色+员工账号权限管理。

机构母户（平台母户）

六、开户流程

6.1 商户入网标准流程（七步）

售前诊断与通道匹配

确认行业准入、资金规模，选择平台母户/独立母户及对应银行通道。

立项审批

店务通银行内部户分账需邮件审批：分管领导审批 → 营销中心审批 → 银行审批（苏商、光大）。

收集商户入网材料

按商户类型提供对应材料（见 6.2），提交入网审核。

银行开户

在线开户，银行自动审核（苏商为静默开户无短信提醒）；对公账户需打款鉴权。

入金配置

运营人员向商户提供银行内部账户，商户到收单机构/挂靠平台变更结算账号，资金结算进分账系统。

分账方开户与规则配置

创建分账方账户（支持单笔/批量），配置分账规则，系统操作培训。

上线运行

对账与结算正式运行；分账方开户数量按商户资金规模控制，超限联系运营。

重要提示：① 分账 ≠ 到账——分账（付款订单）仅入对方虚拟账户，提现才实际出金到绑定银行卡；② 开户为异步流程（打款验证 + 开户结果查询闭环）；③ 绑卡建议使用一类卡；④ 所有通道不承诺固定开户/交付时效。

6.3 开户主体与门槛

  • 主体类型：支持个人、个体工商户、企业开户；个体户可绑法人个人卡；支持非法人申请开户；港澳台及外国法人：苏商银行支持，中信银行需持有中信借记卡。
  • 规模门槛：平台母户注册资本/年交易量无限制；独立母户苏商日均存款 1000 万+，中信年日均 1000 万（有获客可适当降低）。
  • 开户个数：苏商同一企业/个人最多 10 户；一个统一社会信用代码在同一平台首次开户一次，多户走"二次开户"。
  • 地区：全国。

七、对接流程与方式

方式一：SaaS 产品输出（默认）

为客户提供管理后台 + 小程序，一站式完成开户、分账、查询、对账、回单下载全流程，开通即用、零开发。

适合 无技术团队或需快速上线的客户。

方式二：API 接口对接

为有技术能力或需将店务通功能融入既有系统的客户提供接口对接。原则上不对外提供，需单独申请并收取系统对接费（参考：1.5 万元/户接入费，需特批）。

适合 有自研系统、需深度集成的平台型客户。

7.1 API 对接技术要点（以苏商银行为例）

  • 协议：HTTPS + POST，UTF-8；报文业务数据采用 SM4（ECB）国密加密，随机密钥经银行公钥 RSA 加密传输；签名算法 SHA256withRSA。
  • 环境：SIT / UAT / 生产三套环境，银行分配 appCode、channelId 与密钥对。
  • 核心接口域：开户（个人二/四要素、企业绑卡/非绑卡、二次开户、变更）→ 打款认证 → 充值 → 支付分账 → 消费/担保消费 → 提现/非绑卡提现 → 退款 → 余额/明细/状态查询 → 电子回单申请 → 对账文件申请。
  • 对接关键约束：channelSerialNo 全局唯一不可重复；开户类交易为异步、需主动查询结果；企业经营信息需及时补录，否则银行将处置账户；分账与提现是两个独立步骤。

7.2 上线后排障与运营

  • 分账/提现/开户费由考拉御风统一收取，再分润给经销商；
  • 提供测试账号（苏商银行）用于沙箱验证；
  • 运营工单与故障响应走"运营产研沟通群"机制。

八、分账操作流程细化（账单分账 / 外卖分账）

店务通账单分账是"渠道原始账单 + 门店 ID 匹配"的批量分账模式：资金归集到银行中间账户后，按渠道账单逐日拆分到品牌方与各门店的银行虚拟账户。外卖分账是该通用流程在美团/饿了么/微信外卖渠道的实例化。

8.1 前置配置

门店开户与门店 ID

支持代理开户与自主开户（二维码 / PC 链接）；主体分个体工商户（建议）、对公、个人三类，资料提交后由银行侧审核，开户完成后绑定结算卡并短信验证。门店必须录入美团、饿了么门店编号（门店 ID）——系统按账单内的门店 ID 匹配资金并分账，缺失则无法对上账。

收款模板（按订单分账规则）

品牌方不参与分账：仅添加"门店"角色并激活"是否卖家"，公式自动带入"所有结余资金"；
品牌方参与分账：加"平台角色"（公式如 amount*0.05 表示品牌方抽佣 5%，默认入账品牌方余额账户）+ "门店"角色（卖家，剩余全部结余）。

员工角色与权限

建议三类角色：运营经理（门店开户、结算卡变更）、财务操作（上传分账账单）、财务审核（上传渠道原始账单、分账核对）；员工支持多角色权限合并。

平台设置

压款（保证金）、默认提现账期（分账资金冻结天数）、自动提现开关；单门店可在门店详情单独设置提现账期。

8.2 核心流程：账单分账三步

资金确认（财务 · 账单分账）

美团/饿了么等渠道完成连锁结算后，资金于结算日打至银行中间账户；系统自动查询并列出流水，品牌方选择对应流水确认；若流水"标为其他款项"，该笔金额归入平台账户。

账单确认（财务操作）

上传分账账单（大文件进入"文件处理缓存区"异步处理，需等待状态为"完成"），查询后生成按天的账单记录。

门店分账（财务审核）

上传渠道原始账单 → 系统展示调账清单 → 短信验证码确认（发送至经办人预留手机号）→ 系统自动将当日资金分账到各门店与品牌方的银行虚拟账户。

异常处理：分账状态显示"部分分账/失败"仅指银行虚拟账户间划账失败，不影响整体资金数额，由运营排查后代为补发失败部分。

8.3 外卖分账场景细则（美团 / 饿了么 / 微信外卖）

  • 渠道账单结构：美团外卖订单明细（64 列）、微信外卖交易明细（26 列 + 门店透视）、美团买单/团购收益明细、美团打款报表；
  • 多品牌管理：单门店仅可挂一个品牌；多品牌经营时，资金流水到账后需先手动选择所属品牌再分账；
  • 门店管理分层：区域（自定义经营区域）+ 品牌两层管理，适配连锁品牌方与加盟商结构。

8.4 结算、提现与财务统计

  • 自动提现 T+1：分账资金进入分账方余额账户后，冻结指定天数方可提现；
  • 经营统计：按账单日输出门店/品牌方分账明细与总计；
  • 历史账单：分账明细与状态回溯；
  • 门店结算：当日提现状态（成功/部分成功），可查明细报错原因；
  • 门店扣款：扣货款/罚单等，门店余额不足时任务挂起、后续来款定时扣完，款项进品牌方账户；
  • 费用：每日门店分账手续费统计；平台账户页可看余额、待结算余额（可提现）与变更记录。

9.1 电商代运营案例

深圳某抖音代运营服务商

公域电商

场景：代运营多个抖店商户，需从商户销售款中收取代运营服务费。
方案：商户资金归集至银行内部户体系，按固定比例自动抽佣分账，替代人工逐户结算。
价值：抽佣自动化，财务效率提升，杜绝人工错账。

杭州某团 · 京东本地生活服务商

本地生活

场景：作为京东本地生活服务商，面向大量合作商户收取代运营费用。
方案：通过店务通实现商户代运营费用的统一收取与清分。
价值：收费链路系统化，商户规模扩张不再增加财务人力。

广州某拼多多跨境电商品牌

跨境电商

场景：跨境销售结汇后需向上游供应商付款。
方案：通过店务通实现结汇资金归集后向上游供应商定向付款。
价值：资金归集与付款一条链路完成，凭证合规。

某男装品牌经销商

电商店群

场景：抖音矩阵式多店铺经营，资金分散、品牌方回款慢。
方案：多店铺资金统一归集管理后，按约定向品牌方付款。
价值：店群资金一盘棋，品牌回款周期显著缩短。

9.2 餐饮多渠道分账案例

某连锁豆浆品牌

餐饮连锁

痛点：线上外卖/公域渠道 + 线下门店收银，多渠道资金割裂、对账难。
方案：多渠道资金统一归集至总部账户体系，按分账模板执行品牌方抽佣，向门店与上游供应商批量付款。
亮点：归集—抽佣—付款全链路自动化。

某连锁加盟餐饮品牌

餐饮加盟

痛点：直营与加盟并存，线上线下资金分散，管理费抽取与向门店付款效率低。
方案：线上线下资金一体化归集，品牌方按规则抽取管理费，按门店维度向加盟店分账付款。
亮点：门店维度分账付款，总部管控力增强。

某连锁茶饮品牌

700 家门店日均约 200 万元

痛点：线上公域卖券（抖音/美团券）+ 线下收银（POS/码牌），渠道多、门店多、笔数多。
方案："支付账户 + 银行内部户"组合模式：资金统一收款后按杯品维度自动分账给门店与总部，向原料供应商自动/批量付款。
亮点：支撑 700 家门店、日均约 200 万元交易规模稳定运营。
